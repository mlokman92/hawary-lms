# send-appointment-reminders

The evening-before email. At **21:00 academy time** every student with a session
tomorrow is told what is still on and what **staff** cancelled. Instructors are
not reminded. The why is in `docs/appointments.md` → *Reminders: the evening
before*.

## How it runs

| piece | what |
|---|---|
| `cron.job` **`appointment-reminders`** | `0 * * * *` — posts `{}` here every hour |
| `appointment_reminders_due(_at)` | the rows due at `_at`; empty outside 21:00–23:59 academy time |
| `appointment_reminders_secret()` | the Bearer token the job sends, from Vault `appointment_reminders_cron` |
| `appointments.reminder_sent_at` / `reminder_id` | stamped per session the email listed |

Deployed with **`verify_jwt: false`** — the caller is pg_cron, which has no user
JWT. The function refuses anything without the Vault token (401).

## Dry run

Sends and stamps nothing; `at` is honoured only here. From the SQL editor:

```sql
select net.http_post(
  url := 'https://vpklztxqkvqmmzsxfqgp.supabase.co/functions/v1/send-appointment-reminders',
  headers := jsonb_build_object('Content-Type', 'application/json',
    'Authorization', 'Bearer ' || public.appointment_reminders_secret()),
  body := '{"dry_run": true, "at": "2026-09-23T13:00:05Z"}'::jsonb,
  timeout_milliseconds := 60000);

-- a second later, with the id it returned
select status_code, content::jsonb from net._http_response where id = <id>;
```

Or skip the function and ask the SQL directly:
`select * from public.appointment_reminders_due('2026-09-23 13:00:05+00');`

## Did last night's run work?

```sql
-- the job fired, and what the function said back
select start_time, status, return_message from cron.job_run_details
 where jobid = (select jobid from cron.job where jobname = 'appointment-reminders')
 order by start_time desc limit 5;
select created, status_code, content from net._http_response order by created desc limit 5;

-- after 23:59 MYT: what was owed tonight and still never went out (should be empty)
select * from public.appointment_reminders_due(
  ((now() at time zone 'Asia/Kuala_Lumpur')::date + time '23:59') at time zone 'Asia/Kuala_Lumpur');
```

`reminder_sent_at` set with `reminder_id` null means the student had no address.
The Resend id is the join key into the provider's log.

## Kill switch

```sql
select cron.alter_job((select jobid from cron.job where jobname = 'appointment-reminders'), active := false);
```

`active := true` to resume. **Do not unset `RESEND_API_KEY`** — four other mail
functions share it.

## Secrets

Nothing new. `RESEND_API_KEY`, `INVITE_FROM_EMAIL`, `APP_URL` are shared with the
other mail functions; the cron token lives in Vault and was generated by the
migration.
